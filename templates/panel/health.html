About these checks

  • {% include "panel/_health_icon.html" with status="ok" only %}Working. Nothing to do.
  • {% include "panel/_health_icon.html" with status="warn" only %}Needs attention. The site works, but something should be done soon.
  • {% include "panel/_health_icon.html" with status="fail" only %}Broken. Visitors or members are affected now, or the site or its data is at risk.
  • {% include "panel/_health_icon.html" with status="unknown" only %}Couldn't check. The check got no answer; that isn't a fault in itself.
  • {% include "panel/_health_icon.html" with status="off" only %}Not set up. Something optional that hasn't been set up.
  • {% include "panel/_health_icon.html" with status="na" only %}Not applicable here. Only matters on the live site.

Most checks run whenever this page opens. The ones that fetch the site over the internet or look through files on the server run when someone presses “Run all checks”, and daily once the webmaster has scheduled manage.py health_check. An outside monitor can watch /healthz, which answers “ok” while the site and its database work.
